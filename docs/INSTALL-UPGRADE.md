# 安装、部署与升级

## 新电脑

1. 安装并登录 Codex，安装 Node.js 22 或更新的兼容版本，准备 cloudflared 和已有固定隧道。Windows 使用当前用户登录模式；本项目不配置无人登录的系统服务。
2. 运行 `PaneFlow-Desktop-<版本>-Setup.exe`。新安装配置默认保存在当前用户应用数据目录，与程序文件分离。不要把已有便携数据目录作为覆盖安装目标。
3. 设置 → 安装、部署与升级 → 打开配置向导。Node 路径自动检测；填写固定 HTTPS 域名、cloudflared 完整路径、已有隧道配置路径和 ID、工作目录及本机端口。
4. 隧道配置的该域名应指向 `http://127.0.0.1:<端口>`。点击检测，再保存配置。向导不会创建域名、创建隧道或改写现有隧道文件。
5. 点击启动。中继仅监听本机；只有本地和公网都返回本次启动的实例标识才算通过。已有外部服务、端口冲突或活跃旧部署会阻止重复启动。
6. 连接测试通过后开启登录自启。选择“下次打开应用时启动此配置的公网服务”并保存，才会在应用启动时启动自有中继和隧道。

已有 `public-companion-supervisor`／计划任务部署继续沿用原方式。不要同时打开新向导的自启；更新程序时保留原 `data/public-companion`、Cloudflare 配置及计划任务。该目录含私密身份，不应上传公开仓库。

手动覆盖旧版自定义安装时请选择原程序目录；应用内升级会明确传入该目录。安装器不会执行旧卸载器，也不会按进程名关闭其他实例。目标程序被占用时请关闭对应实例后重试。卸载保留未知用户文件；清单文件删除失败则保留卸载入口。历史阶段安装包仅用于留档；当前统一发布版本为 0.8.2，验证范围见对应更新记录。

## Android

安装同签名的 `PaneFlow-Android-<版本>.apk`，不要卸载旧 APP。包名固定为 `com.codexpane.companion`；卸载会丢失 Android Keystore 中的私钥。

设置 → 我的电脑可分别接入多台电脑。可粘贴链接，或选择“扫码输入配对链接”；扫码仅填入输入框。点击继续后，仍须在电脑核对相同六位数字并确认。

后台连接按电脑单独设置；新电脑默认不开启。电脑离线、当前轮次活动、队列未结束、等待审批或回执未确认时，升级会暂缓。0.8.2 起不再要求历史列表中所有会话均空闲，其他会话的运行／未知历史状态不作为 Android 更新锁。操作记录中的 unknown 可逐项人工核对为已完成或确认未执行，需要再次确认；记录和核对时间保留，不会因此重新发送任务。

原 0.8.0／未修复的 0.8.1 如果提示“还有运行中或未知状态的会话”，请从 [0.8.2 Release](https://github.com/kismet84/paneflow/releases/tag/v0.8.2) 下载通用 APK，经系统安装器同签名覆盖一次，保留数据和绑定。旧检查运行在客户端本地，重新下载原旧版本或只更新 Windows 不会解决；不要为通过检查而停止无关电脑任务。

## 明确确认的更新

Windows 配置向导和 Android 设置页都有检查更新入口。固定读取本仓库 GitHub Release 的 `update.json`；目前没有公开发布清单时会提示尚未发布，不会虚报最新版本。

- 清单包含产品版本、协议兼容范围、说明、安装包大小和 SHA-256。下载仅允许项目发布资产及限定的 GitHub HTTPS 重定向。
- Windows 下载后再次确认，阻止新任务，备份旧程序和配置，再安装。新版以维护状态验证 Codex 与已启用的自有部署；确认成功后恢复操作。
- 安装器失败时恢复旧程序。新版启动失败时先请求其停止自有服务和 Codex，验证退出确认后再恢复；无法证明进程退出则报告 `recovery-required`，保持文件原位并保留备份，不能直接覆盖仍可能被写入的数据。
- Windows 恢复材料位于数据目录 `updates/apply-<时间>/`：`plan.json`、`result.json`、`backup/`。原程序及失败程序、原数据及失败数据分别保留。不要上传该目录。
- Android 校验包名、versionCode、minSdk 与当前安装证书；备份本机加密状态和身份引用后交系统确认安装。系统拒绝安装时旧 APP 和数据保留，私钥不导出。
- 程序和数据互相包含、路径含目录联接或符号链接时停止 Windows 自动升级。先人工复制、核对并分离数据；不静默迁移或重建身份。

## 签名与发布

当前本机验收 APK 沿用原 debug 签名以保留现有绑定；Windows 安装包没有代码签名证书。这不是生产签名承诺。

CI 的手动发布流程要求受控 Android 密钥，缺少配置直接失败，不使用随机 debug 签名替代。仓库 Secrets：

- `PANEFLOW_KEYSTORE_BASE64`
- `PANEFLOW_KEYSTORE_PASSWORD`
- `PANEFLOW_KEY_ALIAS`
- `PANEFLOW_KEY_PASSWORD`

本地 release 构建对应使用 `PANEFLOW_KEYSTORE_FILE` 和其余三个环境变量。签名材料始终在仓库外；更换证书不能无损覆盖现有安装，应先明确迁移策略。

`.github/workflows/checks.yml` 检查协议、认证、任务、桌面构建与 Android；`.github/workflows/release.yml` 仅手动触发，生成安装包、校验清单、更新说明和 `update.json`，不自动创建公开 Release。审核产物后，以 `v<版本>` 标签发布全部资产，应用才会发现更新。配置 workflow 文件不代表已在 GitHub 成功运行。
